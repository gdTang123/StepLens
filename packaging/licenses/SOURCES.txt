FreeType 2.14.3
  vcpkg 基线 9eec002df1cd109f8f104cd966a763daf9751489 的 versions/baseline.json 写 freetype baseline 2.14.3、port-version 0。
  许可证正文来自标签 VER-2-14-3 的 docs/FTL.TXT：
  https://github.com/freetype/freetype/blob/VER-2-14-3/docs/FTL.TXT
  端口用 GitLab 标签 VER-2-14-3。
  产品清单把 opencascade 的 default-features 关掉，只打开 freetype。该特性依赖 freetype 时写了 default-features false（见 occt-7.9.3-vcpkg-port/vcpkg.json）。因此 freetype 端口自己的默认特性 brotli、bzip2、png、zlib 不在这条锁定依赖里。subpixel-rendering 也没有打开。

  gtest 在清单里，但是测试目标用的。产品可执行文件的 CMake 不链接它，不把它算成绿色版运行库。
  zlib 1.3.2、bzip2 1.0.8、libpng 1.6.59、brotli 1.2.0 的许可证和端口副本仍在本目录，只因为上一轮按 freetype 端口的默认特性收过。上面已写明产品这条依赖把 freetype 的默认特性关掉了，所以它们不在锁定图里。若以后 dumpbin 真的列出这些 DLL，副本可以对照；这不是已经证明 exe 链接了它们。
  这些端口的补丁条件：zlib 的 0001-no-version-script-on-ohos.patch、brotli 的 install.patch 与 pkgconfig.patch、bzip2 的 fix-import-export-macros.patch 都写在各自 portfile 的 PATCHES 里，没有 Windows 条件。libpng 的 cmake.patch 同样无条件；apng 补丁只在 feature apng 打开时下载，当前没有这个 feature。

MSVC 2022（v143）
  仓库不猜测 Visual Studio 补丁号。打包时从实际使用的 dumpbin 路径读取 VC\\Tools\\MSVC\\<版本>，再从同一套 Visual Studio 的 VC\\Redist\\MSVC 读取官方目录。
  出处：
    https://learn.microsoft.com/en-us/cpp/windows/determining-which-dlls-to-redistribute?view=msvc-170
    其中写明：再发行包的主版本必须与工具集相同，次版本相同或更高；2015、2017、2019、2022 的工具集版本号兼容，可以使用更新的再发行文件，不支持使用更旧的。应用本地部署是把这些目录里的库放到 exe 旁边。只能再分发 Redist.txt 或在线 REDIST list 点名的文件，不能再分发调试版。
    https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files?view=msvc-170
    其中写明：再分发限于有 Visual Studio 许可的用户，并受微软软件许可条款约束。VS 2022 的 REDIST list 见该页指向的 Distributable code files for Microsoft Visual Studio 2022。应用目录部署是允许的做法，微软同时说明从维护角度不推荐。2015 至 2022 的最新再发行文件二进制兼容。VS 2022 的再发行文件位于 %VCINSTALLDIR%Redist\\MSVC\\v143，单个 DLL 位于 %VCToolsRedistDir%\\[architecture]\\Microsoft.[toolset].[library]。
  脚本不要求再发行目录的补丁号与工具集补丁号相同。点分版本目录选不旧于工具集的最新一个；只有 v143 这类没有点分版本的官方目录时，使用该目录并记下名字，不把它编成补丁号。
  没有 Redist.txt、读不到工具集版本、或目录都更旧时失败。不从 System32 复制，也不下载 DLL。
  在线 REDIST list 的全文没有收进仓库。没有本地 Redist.txt 就不能逐项核对允许的文件名，因此不把材料说成已经齐备。

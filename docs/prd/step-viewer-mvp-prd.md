# PRD：STEP 模型轻量查看器 MVP（v0.2）

作者：产品经理 ｜ 日期：2026-11-03 ｜ 状态：老板已确认 v0.1 问题，待架构师评估性能指标
技术栈：C++20、Qt 6、OpenCASCADE (OCCT)、CMake ｜ 平台：Windows 10/11 x64 ｜ 周期：2–3 周（超大文件方案对工期的影响待架构师评估，见第 6.2 节）
发布形式：绿色版 zip，解压即用，不做安装包，不做代码签名 ｜ 使用范围：仅老板和团队内部使用，不对外

## 1. 产品目标和目标用户

**产品目标**
- 做一个"解压就能用、打开就能看"的 STEP/IGES 查看器：启动快、绿色版免安装、不需要 CAD 授权。
- **200 MB 以上的大装配要能流畅打开和浏览**，这是核心场景，不是边缘场景（老板确认：实际文件经常超过 200 MB）。
- 覆盖"看模型、量尺寸、看结构、截图沟通"四件事，满足内部日常评审和沟通，不做建模和编辑。
- 2–3 周交付可用 MVP，为后续版本（格式扩展、标注、剖切等）打好架构基础。

**目标用户**（仅内部使用，不对外发布）
1. 老板：经常需要查看 200 MB 以上的大装配，快速看外形、看结构、量关键尺寸、截图沟通，不想开重型 CAD。
2. 内部工程团队（机械/结构工程师等）：收到供应商或同事的 STEP/IGES 文件，想快速看外形、找零件、量尺寸，不想开重型 CAD。

说明：v0.1 中的采购、工艺、质检、销售、客户等角色不在本版范围内。工具只在团队内部分发，界面可以按熟悉 CAD 的工程人员来设计，不需要为外部用户做额外引导。

**核心使用场景**
- S1 打开文件 → 旋转缩放看外形 → 关闭。（最高频）
- S2 打开装配 → 在装配树里找零件 → 隐藏遮挡件 → 查看内部零件。
- S3 选两个点/边/面 → 量距离或角度 → 截图发给同事。
- S4 打开 200 MB 以上的大装配 → 看得到加载进度、需要时可以取消 → 加载完成后流畅地旋转、缩放、在装配树里找零件。（核心场景）

## 2. MVP 功能清单

优先级定义：P0 = MVP 必须有，缺了不能发布；P1 = 计划在 MVP 内做，时间不够可以顺延；P2 = 下一版。

### P0（必须）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| P0-1 | 打开 STEP 文件（.step/.stp，AP203/AP214/AP242 几何部分） | 通过"文件-打开"、拖拽到窗口、命令行参数（`程序名.exe 文件路径`）三种方式都能打开（双击文件关联打开见 P1-7）；第 7 节样例集中的全部 STEP 文件（含单零件和装配）都能正确显示，形状与参考软件（如 FreeCAD）目测一致；文件损坏或格式不支持时弹出中文错误提示，程序不崩溃。 |
| P0-2 | 打开 IGES 文件（.igs/.iges） | 同 P0-1 的三种打开方式；第 7 节样例集中的全部 IGES 文件都能正确显示（含曲面模型）；失败时有错误提示且不崩溃。 |
| P0-3 | 三维显示 | 着色+边线模式默认开启；保留 STEP 中的零件颜色，无颜色时用统一默认色；打开后自动"适应窗口"让模型完整居中。 |
| P0-4 | 视图操作：旋转、平移、缩放 | 鼠标左键拖动=旋转，中键拖动=平移，滚轮=以光标位置为中心缩放（键位已定稿）；操作在各档样例文件上流畅（含超大档，见第 5 节）；提供"适应窗口"按钮和快捷键 F。 |
| P0-5 | 标准视图 | 工具栏一键切换前、后、左、右、上、下、等轴测 7 个视图，切换后模型完整可见；右下角显示坐标轴指示器（XYZ 三轴）。 |
| P0-6 | 装配树 | 左侧面板按 STEP 产品结构显示层级树，节点显示零件/组件名称（无名称时显示"未命名-序号"）；点击树节点 = 三维视图高亮对应零件，点击三维零件 = 树中定位并高亮对应节点；每个节点有显示/隐藏勾选框，父节点隐藏时子节点一起隐藏；IGES 或无结构文件显示为单一根节点。 |
| P0-7 | 距离测量 | 支持点到点、点到边、点到面、边到边、面到面（平行面）的最小距离；选择时有捕捉高亮（顶点、边、面）；结果显示数值（单位 mm，保留 3 位小数）并在视图中画出测量线和标注；与参考软件对比误差 ≤ 0.001 mm；按 Esc 取消，可一键清除所有测量。 |
| P0-8 | 角度测量 | 支持两条直线边、两个平面、直线边与平面之间的夹角；结果单位为度，保留 2 位小数；与参考值误差 ≤ 0.01°；选到不支持的组合（如曲面）时提示"不支持该组合"。 |
| P0-9 | 截图导出 | 将当前三维视图导出为 PNG（默认）或 JPG；导出图包含测量标注，不含界面工具栏，不加水印或 Logo；默认分辨率等于视图窗口大小；保存时弹出文件对话框，默认文件名为"模型名_时间戳.png"。 |
| P0-10 | 稳定性与基本体验 | 打开过程中显示进度/忙碌提示，界面不假死；第 7 节样例集中小、中、大三档的全部文件连续打开、关闭各 3 轮不崩溃、无明显内存持续增长；超大档按 P0-11 验收；界面为中文。 |
| P0-11 | 大文件打开与流畅浏览（200 MB 以上） | 用第 7 节超大档样例（X-01～X-08）验收，满足以下全部要求：① 后台加载：加载放在后台线程，加载全程界面可响应（可拖动窗口、可点菜单），不出现"未响应"；② 进度可见：显示加载进度（阶段文字 + 百分比或进度条，如"读取文件 / 解析结构 / 生成显示"），进度长时间不动时也要有忙碌提示；③ 可取消：加载过程中可随时点"取消"，取消后回到打开前的状态，内存释放，程序不崩溃；④ 浏览流畅：加载完成后旋转、平移、缩放流畅，无明显卡顿；装配树展开和点击高亮及时响应；⑤ 内存不溢出：在第 5 节基准机（16 GB 内存）上打开超大样例不出现内存耗尽，峰值内存不超过第 5 节约定的上限；⑥ 不崩溃：超大档样例各连续打开、关闭 3 轮不崩溃；超出能力的文件（如内存不足）给出中文提示而不是闪退。具体时间、帧率、内存数值见第 5 节，均「待架构师确认」。 |

## 3. 不做什么（非目标）

- 不做任何建模和编辑：不改几何、不改装配结构、不保存回 STEP/IGES。
- 不做格式转换导出（如导出 STL/OBJ），MVP 只导出截图。
- 不做 2D 工程图、DWG/DXF。
- 不做 PMI/GD&T、材料、注释等制造信息显示（放 P2）。
- 不做多文档/多标签，一次只打开一个文件。
- 不做云端、账号、协作、批注分享。
- 不支持 macOS/Linux（架构上不刻意绑死 Windows，但不测试、不发布）；Windows 只支持 10/11 x64，不支持 Windows 7/8。
- 不做插件系统和脚本接口。
- 不做自动更新和授权/激活。
- 不做安装包（NSIS/MSI 等），只发布绿色版 zip；不做代码签名。
- 不对外发布、不对外销售，只在团队内部使用。
- 不做英文界面（放 P2）；截图不加水印、公司 Logo 或文件名/日期等附加信息。

## 4. 界面布局（文字说明）

整体为经典单窗口布局，从上到下：

1. **菜单栏**：文件（打开、最近文件、导出截图、退出）、视图（标准视图、显示模式、适应窗口、显示/隐藏面板）、测量（距离、角度、清除测量）、帮助（快捷键说明、关于）。
2. **工具栏**（菜单栏下方一行图标按钮，悬停显示中文提示）：打开｜适应窗口、7 个标准视图｜显示模式｜距离测量、角度测量、清除测量｜截图。
3. **主区域**（左右分栏，分隔条可拖动）：
   - 左侧"装配树"面板，默认宽约 260 px，可折叠/拖出为浮动窗口；顶部有搜索框（P1，按名称过滤）。
   - 中间三维视图，占主要空间；背景为浅灰到白的渐变；右下角坐标轴指示器；测量结果以标注形式直接画在视图中。
   - 右侧"属性/测量结果"面板（P1，默认收起）：选中零件时显示属性，测量时显示测量列表。
4. **状态栏**：左边显示操作提示（如"请选择第一个元素"），中间显示当前选中对象，右边显示单位和文件名。

空状态：未打开文件时，三维视图中央显示"拖拽 STEP/IGES 文件到这里，或点击打开"。

加载状态：打开文件后，三维视图中央（或状态栏）显示加载阶段、进度和"取消"按钮；加载期间菜单和窗口操作保持可用（见 P0-11）。

测量交互：点击测量按钮进入测量模式 → 状态栏提示选择第一个元素 → 选第二个元素 → 显示结果 → 继续下一组测量，Esc 或再次点击按钮退出。

## 5. 性能目标

测试基准机：Windows 10/11，Intel i5 第 10 代或同级 CPU、16 GB 内存、集成显卡（Intel UHD 630 级别）及以上。

**200 MB 以上文件流畅可用为 P0 必须**（老板确认这是核心场景）。下表的"目标值"一律「待架构师确认」；"产品期望参考值"是 v0.1 产品侧提出的期望，只作参考，需架构师结合 OCCT 能力和第 7 节样例实测评估后定稿，可上调或下调。

文件大小口径：按 Windows 资源管理器显示，1 MB = 1024 × 1024 字节。

### 6.2 待架构师确认事项

1. **性能数值**：第 5 节表中所有"目标值"（各档首次显示时间、完整加载时间、帧率、内存峰值、取消响应时间、装配树响应、冷启动、截图、zip 体积），请用第 7 节样例在基准机上实测后给出。
2. **超大文件技术方案**：200 MB 以上文件对 OCCT 读取速度和内存压力很大，请评估以下手段的可行性和组合：
   - XCAF 装配结构先行显示（先出装配树和包围盒，再逐步出几何）；
   - 按需三角化 / 渐进式三角化（先显示粗网格，再细化；隐藏的零件不三角化）；
   - LOD / 简化显示（交互旋转时降精度，停下后恢复）；
   - 多线程读取与多线程三角化；
   - 相同零件的实例共享（避免重复几何占内存）；
   - 加载取消的实现方式（OCCT 读取过程中如何安全中断）。
3. **内存上限**：在 16 GB 基准机上，超大档的内存峰值上限定多少合适。
4. **超大文件上限**：建议程序声明支持的最大文件大小（如 500 MB 或 1 GB），超出时给出提示。
5. **工期影响**：上述方案能否在 2–3 周内完成；如不能，需要多少额外工期，或哪些部分可以先做简化版。
6. **基准机配置**：集成显卡（UHD 630 级别）对超大档是否够用，是否需要把基准机提高到独立显卡。

### 6.3 仍待老板确认的问题

1. **工期与大文件的取舍**：如果架构师评估超大文件流畅浏览需要超过 2–3 周，是延长工期，还是 MVP 先保证"超大文件能打开、不崩溃、可取消"，流畅度在下一版继续优化？（待架构师给出评估后再请老板拍板）
2. **超大文件的实际规模**：日常最大的文件大约多大（300 MB？500 MB？1 GB？）、多少个零件？公开样例最大约 357 MB，如果真实文件明显更大，需要按第 7.3 节合成更大的测试文件。

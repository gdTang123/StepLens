# T65 软取消勘误（打开 B 恢复 A）

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-26（Asia/Shanghai） |
| 批准 | 老板明确批准：软取消打开 B 后恢复 A 原文档/树/显隐/视图；接受暂留旧模型额外峰值内存 |
| 对照 | `docs/design/step-viewer-architecture.md` §4.6 / §6.6；`docs/prd/step-viewer-mvp-prd.md` P0-11 |

## 新口径

1. **空闲取消**：无加载时取消 / Esc 为空操作。
2. **加载中取消（已有 A，正在开 B）**：丢弃 B 的邮箱结果；宿主上的 A、装配树、显隐与视图保持不变。不 `clear` 到空闲方块。
3. **首次打开取消（无 A）**：不向宿主提交 B；回到空闲方块。
4. **成功完成后 Esc**：不清除已成功显示的文件。
5. **失败**：B 失败不误销 A；宿主与树仍为 A。
6. **提交时点**：B 仅在后台成功完成（含三角化）后才 `host.reset(B)` 提交；加载过程中 A 继续显示。
7. **旧模型释放时点**：A 的 `DocumentModel` 在 B **成功提交**时随 `SceneHost::reset` 交出，随后台 Close；取消/失败路径不释放 A。
8. **内存成本**：打开 B 期间接受 **A+B 双文档峰值**（A 仍在宿主，B 在邮箱/加载线程）。与旧“省内存、取消回到空闲方块、不保留上一文件”口径不同，以本勘误为准。

## 非目标（本勘误不改）

- 不重写 STEP/IGES 读取器。
- 不引入硬取消 / 子进程加载。
- 不改变令牌检查点与 `LoadSession` 共持约定。
